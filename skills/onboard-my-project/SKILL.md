# Onboard my Project

Use for an explicitly selected existing project, update, repair or recovery. Onboarding checks workspace readiness first and hands missing required tools to `prepare-my-workspace`, then inspects the project, assesses the complete Toolkit catalog, makes authorized changes recoverably, and leaves guidance, commands, checks, limitations and an undo location.

Read [the procedure](references/procedure.md) for onboarding and [apply and recovery](references/apply-and-recovery.md) for authorized file changes or undo. Read [managed planning](references/managed-plan.md) only when using the managed dispatcher; when presenting its proposal, read [Reviewed Configuration](references/reviewed-configuration.md). Read [qualification](references/qualification.md) only for selected managed activation or adapter validation. Inspect-only and plan-only requests never install or write. Preserve permissions, writer ownership, user edits and recovery provenance. Ordinary development needs no runtime activation or qualification campaign.
