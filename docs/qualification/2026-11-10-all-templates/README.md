## Fresh cases and results

The 20 independent cells covered five cases, two models and prose/template arms. Four produced briefs were each consumed once in a fresh session. The prior successful review/handoff cases required no new review inference.

- **Interface and Claude-selected documentation:** a synthetic static label-trimming page made all eight project shapes and setup record applicable. Both treatments retrieved every project shape, setup and task layouts, preserved original statements and source bytes, and produced all authorized outputs. Both still deferred a concrete next delivery rather than proposing a smallest useful task and observable acceptance. Their honest pending-browser/accessibility statements are not failures of actual browser behavior; that behavior was not tested.
- **Minimal and customized documentation:** both template arms preserved original project statements, filenames, nested instructions and fixture choices. All treatments now read the project layouts, unlike the earlier Go trials. However, minimal outputs treated Python prerequisites as not established despite inspected Python code/checks. Luna's minimal setup also said the date was not supplied although the prompt supplied it. Luna's customized treatment still omitted a concrete next delivery. Haiku's customized treatment correctly described two assertions but copied template-origin author instructions into the new setup record.
- **Local PR body and title:** both treatments read and used `pull-request.md`, named exact candidate/base commits from real disposable local Git history, cited coordinator-run checks as supplied evidence, retained pending independent review and generated `[BLOCKED]` titles and draft bodies. Nothing was published remotely by these workers. Prose controls also described blocked bodies but omitted the prefix from their separate title files; this is descriptive, not a causal uplift claim.
- **Worker briefs and consumption:** all four producer sessions wrote bounded briefs without repairing code. All four fresh consumers then changed the original subtraction to addition, preserved `AGENTS.md`/`check.py`, wrote handoffs and passed the coordinator's protected check. No worker claimed to have executed that check. Luna's treatment brief had no missing mandatory support path in the relocated consumer copy. The Haiku prose brief similarly required an omitted owner document; Luna's prose consumer also encountered that omitted owner. Those three consumer environments do not prove clean transport of their full assignments. ## What remains unresolved

1. Require a concrete, explicitly proposed next task and observable criterion without presenting the proposal as an accepted requirement. Current cautious outputs often replace this with “owner to decide.”
2. Separate unknown minimum versions from inferable prerequisites. A Python fixture using the standard library still needs Python; a missing manifest does not make that requirement unknowable.
3. Distinguish original notes from template-origin author instructions in both directions: preserve originals and remove copied author notes. Haiku's customized setup retained the latter.
4. Transport every referenced read-only dependency and bind checkout identity before judging brief consumption. This is an operator repair, not an excuse to retry the same task to green.

No production edit or repair comparison was made after seeing these results. The 24-session schedule was exhausted; no extra model/grader call or automatic retry was added. This evaluation supplies failed and partial evidence, not permission to mark templates qualified.

## Instruction change and comparison limits

The user saw the exact routing change before inference. The complete common preservation clarification had already been disclosed in the preceding trial and was applied to both arms. It preserves original statements verbatim in their original file, removes only template-origin notes, requires source-grounded counts and distinguishes proposed scope from observed requirements.

**Before — disposable documentation owner routing:**

```text
For the document responsibilities, read `.workflow/templates/README.md` with the read tool, then select the relevant linked layouts. Markdown links are relative to the containing file; pass project-root-relative paths to tools. For example, its `project/product.md` link resolves to `.workflow/templates/project/product.md`. Read `.workflow/templates/task-record.md` for the final handoff. Use applicable shapes; no new files are authorized by a shape. Do not copy package-relative author links into generated documents.
```

**After:**

```text
Read `.workflow/templates/README.md`, every `.workflow/templates/project/*.md` shape, `.workflow/templates/setup-record.md` and `.workflow/templates/task-record.md` with the read tool before adapting the documents. Use the applicable fields of every relevant shape; explicitly explain inapplicable shapes. Template reading grants no new files or actions. Resolve links from each generated destination; remove only template-origin author notes and placeholders.
```

[instruction-changes.json](instruction-changes.json) preserves both paragraphs and the exact common rule block. [prompts.json](prompts.json) preserves every prompt and actual owner document. PR and brief cases were new cases, not a hidden change to earlier instructions.

**Method limitations:** the two arms share broad preservation, factuality, scope and nine-responsibility prose requirements, but this operator did not restate every detailed template field in the prose arm. Therefore, this is not a strict equal-requirements causal comparison. Missing fields in treatment outputs are still directly observable failures against the layouts they were told to use. No uplift, savings or reliability estimate is claimed. Runner/case bytes were hashed before inference; the scheduler was protected and retained unchanged but its digest was recorded after execution, not frozen beforehand. The consumer-context omission is retained as an operator limitation.
