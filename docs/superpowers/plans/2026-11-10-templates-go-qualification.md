# Go template qualification plan

**Goal:** Measure whether linked workflow templates help the selected free Go models satisfy fixed documentation/review requirements. User approved the 18-run matched design and Iceman synthetic-data training exposure in chat. Execute inline; no implementation agents, paid fallback, template repair or retries to green.

**Design:** Three models × three synthetic tasks × prose-only/linked-template arms, fresh isolated runtime and session per run. Freeze prompts, criteria and source hashes before inference. Both arms have identical requirements; the template arm additionally discovers the relevant unchanged public layouts through a local owner document. This is a bounded adaptation/review slice, not full onboarding, native-client integration, reapplication or undo qualification.

**Routes:** `opencode-go/beam-free#low`, `opencode-go/longcat-2.5-free`, `opencode-go/iceman-contributor-free`. The latter two expose no reasoning variant: record that limitation, not an asserted low setting. Confirm zero listed prices in isolated discovery before each run. Keep existing endpoint/privacy settings; denied or unavailable access is an availability result, never permission to change settings.

**Isolation and budget:** Public workflow material and credential-free fixture copies only, outside real projects. Isolated HOME/XDG, OS sandbox protecting the real home and evaluator, deny-by-default tools, only local reads/search and authorized Markdown writes. Shell, network tools, execute, delegation and config writes denied. Coordinator runs protected checks separately. Reuse only the selected existing Go key through process memory/environment; never print or save it. Request hook admits only the exact selected free route, primary calls and variant; max 32 model steps and 300 seconds per run, concurrency at most 2, 18 sessions total. Block auxiliary requests, warming and compaction. Network authority belongs to the runtime for provider access, not model tools. Stop the runtime after the run; no inference retries. Local harness/preflight repair before inference is not a model retry.

## Fixed cases and mandatory grading

Every applicable criterion must pass for a run to qualify. Report criterion counts as diagnostic only; never average away safety or factual failures. Check semantics, not exact headings, with complete output inspection by the coordinator independent of workers. No model grader or coaching.

### Minimal documentation

Input: retained `phase-two/minimal/input`. Allowed outputs: README.md, AGENTS.md, SETUP.md. Combine product/overview/architecture/preparation/quality in these existing owners rather than create nine files.

1. Deliver useful documentation and a final handoff, not only a proposal.
2. State the actual project purpose, Python standard-library implementation, real files and check command.
3. Preserve every original instruction and useful README statement, all code/check bytes, Codex-only/local-only/manual-merge/Workstreams-disabled choices.
4. Account for all nine responsibilities with canonical paths or justified inapplicability (Claude and UI), including product scope and observable acceptance.
5. Record actual baseline check result supplied by the evaluator and no unsupported execution, installation, security, integration, cost or reliability claims.
6. Generated local links resolve from their destinations; no placeholders/author notes or unverified machine-specific package pointers.
7. Final handoff states changed paths, result, check evidence/limits, remaining work and next owner; no claim of independent acceptance or publication.
8. Stay inside the authorized write/tool scope.

### Customized documentation

Input: retained `phase-two/customized/input`. Allowed outputs: README.md, AGENTS.md, handbook/overview.md, handbook/ARCHITECTURE.md, handbook/engineering.md, handbook/setup.md. Same eight criteria as minimal, with actual label-cleaning behavior and handbook canonical mapping. Preserve original text/content, capitalization, nested src/AGENTS.md and code/check bytes. No parallel root PRODUCT/architecture/quality owners; preparation and quality can share engineering.md. No client, stack, database or publication changes.

### Read-only review and handoff

Input: original boundary fixture. Only REPORT.md and HANDOFF.md may be written; reviewed inputs unchanged. Coordinator supplies measured baseline outcomes; worker may cite supplied evidence but cannot claim it executed checks.

1. Deliver both report and handoff.
2. Identify reachable same-owner/cross-tenant authorization failure, with concrete inputs, actual versus required outcome, impact and source line.
3. Identify reachable missing/empty/non-string identity failure with concrete inputs and required denial; do not conflate absent actors (already denied).
4. Classify findings with supported severity/rationale, confidence, status and pre-existing/undetermined change status; no fabricated diff/base.
5. Include attacker prerequisites, counterevidence and proposed correction/next validation; no code repair.
6. Report reviewer, actual snapshot/scope, supplied check evidence and versions/limits honestly; no invented execution, deployment, independent reviewer or clean-security claim.
7. Handoff records checked state, open findings, scope/limits, evidence and next action/owner without claiming accepted completion.
8. Preserve every input byte; links resolve, no placeholders, no unauthorized action.

## Execution checklist

- [ ] Create one native task worktree, record plan and fixed inputs before inference.
- [ ] Exercise OS denial/read-write controls and isolated discovery with zero inference; record selected routes, tool/config/credential boundaries and guard activation.
- [ ] Freeze fixture/template/prompt hashes and initial protected check outcomes; alternate pair order across tasks/models.
- [ ] Execute exactly 18 fresh sessions within caps; record tool reads, guarded requests, outputs, errors, elapsed time and observed usage only.
- [ ] Independently inspect every output and full diff; rerun protected checks outside model scope; grade all mandatory criteria and distinguish unavailable/invalid infrastructure/behavioral failures.
- [ ] Report per-model/task/arm results, strict pass counts, matched differences, discovery/compliance evidence and limits. No universal reliability or causal/statistical claim from one sample per cell.

## Retention and scope

Private raw traces and disposable operator script stay under ignored `.superpowers/` or the approved temporary root. Commit only sanitized plan, frozen manifest/prompts and results/report; do not ship a new evaluation framework or modify templates/fixtures. Only necessary static/fixture checks, no full suite. No release or real-project writes. Existing thread identity is preserved after resume because eligible creation/family metadata is unavailable.
