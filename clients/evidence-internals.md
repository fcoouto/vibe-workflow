# Canonical evidence internals

Load only for canonical storage changes or audits, linked plan-v2 completion/status, internal lifecycle closure, or explicit private review-accounting inspection. Apply the [common evidence contract](evidence.md). Current public canonical runtime uses uppercase task states; historical E lowercase schema-3 records keep their original readers, packages, paths and pins. These private operations do not create a compatibility bridge.

## Private review accounting

For explicit review-accounting inspection or storage audits, load [private workflow storage](../skills/prepare-my-workspace/references/private-storage.md). Its `storage owner --cwd` and `storage project-owner` controls resolve existing enrolled accounting or real non-enrolling temporary anchors. Scope observations and stored metadata preserve original owner references and ages across supported repeats/subsets; conflicts allocate nothing. Accounting grants no accepted task scope, detailed-report retention, screening time or activation. Ordinary task evidence operations do not load this procedure.

## Internal canonical schema-3 evidence

Read this section only when changing or auditing canonical evidence storage, or handling linked plan-v2 completion/status; its runtime activation boundary is in [task runtime](runtime.md#internal-canonical-schema-3). Under an accepted schema-3 scope, artifact registration uses a scoped transaction and metadata that binds the artifact owner, digest, byte count, managed file identity/mode, parent-directory identities, dependencies and targets. Task artifacts remain bound to the exact accepted task and physical checkout.

Fresh schema-3 authority creation may add a compact `authority-source-baseline` containing the authority identity, original creation time and runtime digest. Historical `source_contract:1` records this bootstrap provenance only and is not retrofitted. `source_contract:2` is created under the D4 registration protocol, which requires validation of the admission and final-source-hook sources, edges and authorities; those event/source receipts are not contents of the baseline itself. Neither version is a complete source inventory, proof of full lifecycle completeness, membership proof, physical evidence cleanup/expiry implementation, or aggregate verification.

Private owner-only `evidence.close_task` supports one existing `source_contract:2` schema-3 authority. For an already-cancelled task, it requires exact retained coordinator-stop proof and complete, independently reconciled coordinator/check/worker/review assignments with matching D4 certificates, including explicit not-started proofs. A newly acquired independent complete-task stop may cover an actual legacy synchronous-verifier barrier while preserving original cancellation, revision, pins, age and the barrier's failed or stale historical result. For an ordinary completed (`DONE`) task, it requires an actual independent complete-task stop proof while preserving the original completion revision, pins and age; the synchronous-verifier barrier remains historical proof and cannot be treated as a fresh stop. Missing, uncertain, changed, or unknown owners block closure. Legacy version-1 cancellation plus a settled barrier alone remains insufficient; a completion stop followed by cancellation is stale and protected because stop renewal is unsupported. The compact record retains original source refs and ages, numerical check facts, findings/dispositions, worker provenance, stop/reconciliation certificates, and native plus current/historical scope-guidance sources; native usage remains unknown. Historical guidance can continue through exact source proof, but a failed changed-applicability refresh never authorizes new dispatch. Closure preserves the original cancellation or completion state, revision, pins and age; completion closure remains historical and grants no fresh implementation, merge, or delivery authority, while cancellation creates no implementation or delivery success. Assignment markers precede assignment-row removal, then exact task/turn/receipt markers precede their row removal; evidence files remain. Linked/foreign-owner closure, complete temporary review retention, physical deletion/expiry/caps/4096 reclamation, and public lifecycle-closure routes remain unsupported. These internal calls do not qualify native execution or expose a public CLI.

The internal linked evidence-plan version 2 has `linked:{acceptance:[{id,text}],delivery:null|{provider,repository,target,pull_request},companions:[{task,delivery}]}`. Validation checks this listed shape and participant projection; it does not establish that the companion set is complete. Ordinary `verify` still blocks version-2 linked plans. The internal `verify_linked` path can record aggregate verification only when its trusted coordinator caller supplies independently checked current scope and complete participant observations, matching normalized plans, each member's current local proof, and supported shared-criterion/source evidence. A callback, private Python bundle, JSON, retained reference, or digest alone does not authenticate authority or completeness.

The aggregate pointer and readiness change are written only to the selected task. Member preparation may record each peer's ordinary local verification; linked publication does not modify peer rows or publish aggregate pointers there. `implementation_verified` and `delivery_complete` are separate: passing implementation proof does not establish required delivery, and an open or unknown delivery does not by itself invalidate implementation. Linked status rechecks the complete stored member set, current rows/generations and retained sources even when it cannot change readiness; stale or unavailable support is not passing evidence. Genuine failed/unknown results may enter linked history only with settled/proved execution and actual current required-delivery/recovery/source evidence; uncertain execution or missing proof stays protected. A version-2 factual basis applies only when aggregate absence is genuine. Nullable member-verification refs require managed proof no verifier existed; version 1 requires real refs. This owner-bound basis is not a stop or fresh readiness. Host proofs bind it plus each exact member/attempt/assignment/descendant; register each member’s own stop and require all stops before preparation/closure. Never fabricate a verifier or aggregate; ordinary/fresh verification stays strict. It preserves actual states, revisions, pins and original ages, including verifying peers and exactly proved cancelled predecessors. Once every member's independent stop, actual shared-result/source support, and required merged-at-head or approved-null delivery are verified, internal preparation retains an owner-bound compact per member. D4 can then release covered component routes. Foreign raw, content, and recovery dependencies remain protected transitively. Preparation leaves original task, assignment and event rows, states, revisions, pins and ages unchanged. Preparation alone grants no safe closure. Closure rechecks the complete component and recovery dependencies, durably registers the exact per-task candidate, then publishes that task’s safe closure in a separate local transaction. Retries preserve the candidate reference and original age. Retire linked raw rows only after every actual approved member has published safe closure, required support and recovery remain complete, and no independent consumer needs those rows. Retire assignments then task/event rows atomically within each authority; process authorities sequentially. Certificates, metadata and exact markers preserve original identity, outcome, revision, pins and creation/closure times. Historical outcomes, including D4, guidance and replay, grant no fresh readiness. Keep evidence files; physical cleanup remains separate work. This internal path is not exposed by the public task evidence CLI, does not grant canonical activation or native qualification, and never grants merge authority.
