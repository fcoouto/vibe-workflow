# Workflow templates

Author reference, not a routine reading list. Load a template through the policy or skill that owns its use. Templates shape an existing document or record; they neither require a new file nor authorize an action. Fill known facts, keep material unknowns explicit, omit inapplicable sections, and remove unfilled placeholders and author notes from generated documents.

| Template | Owner/use |
| --- | --- |
| [Worker brief](worker-brief.md) | Delegation assignments |
| [Task record](task-record.md) | Progress, reports and handoffs |
| [Review report](review-report.md) | Code, security and project reviews |
| [Pull request](pull-request.md) | Authorized PR publication |
| [Setup record](setup-record.md) | Onboarding decisions and evidence |

## Project documents

The [onboarding procedure](../skills/onboard-my-project/references/procedure.md#adapt-project-documents) maps the nine responsibilities to these shapes. Preserve existing canonical documents, combined destinations, selected clients and their instruction-loading mechanisms. Names below describe templates, not mandated output paths. In particular, use descriptive filenames here rather than `AGENTS.md` or `CLAUDE.md`, so clients do not auto-load a template as instructions for this package.

| Responsibility | Shape |

| Product | [Product](project/product.md) |
| Overview | [Overview](project/overview.md) |
| Shared instructions | [Shared instructions](project/shared-instructions.md) |

| Architecture | [Architecture](project/architecture.md) |
| Design and accessibility | [Design](project/design.md) when relevant |
| Local preparation | [Local preparation](project/local-preparation.md) |
| Quality | [Quality](project/quality.md) |
