# Policy contracts

Installation provides capabilities; Project Onboarding assesses the complete Toolkit component catalog and adopts relevant policies; Runtime determines applicable actions and verifies their outcomes. Agents assess meaning, risk and capability; scripts enforce supported permissions, limits, ownership and evidence requirements. A completed record alone does not prove a correct decision or working enforcement.

## Loading

Project Onboarding assesses the complete Toolkit component catalog. Load each policy contract when its trigger applies; do not require every policy or advanced capability for ordinary onboarding.

During Runtime, read this index and every applicable contract or guide below in full before its guarded action. Read applicable directory instructions and follow triggered dependencies to their complete local procedures. A link, routing summary or line in the entry instructions is not the procedure; leave unrelated material unloaded. No task is too small for a gate, and a request that names the action does not waive it.

- A file whose complete, current text is already in context need not be read again.
- Reassess triggers when scope changes and before implementation, delegation, completion or merge. After resume or context loss, restore missing instructions and check actual project state.
- Resolve missing, conflicting or truncated instructions before the dependent action; continue independent authorized work. Preserve normal instruction precedence and task-specific policy pins.

Keep policy adoption, action applicability and action satisfaction distinct. Missing capabilities or unknown applicability cannot count as inapplicable or satisfied. Ordinary native editing, tests and review need no managed task state or runtime activation. Block only work that depends on a missing prerequisite; never silently skip an applicable mandatory requirement. Optional enforcement and advanced execution acquire only their own prerequisites when selected.

Use deterministic tooling or direct execution when sufficient. Consider delegation
for useful context isolation, specialization, required independence or independent
parallel work; only then load the dispatch contract. Direct work still follows
planning, verification and applicable review requirements.

Policy contracts retain their adopted project scope. Rows labelled "Repository" apply only to work on this toolkit repository; other enrolled projects keep their own guides, commands and project rules.
